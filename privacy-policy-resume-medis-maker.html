Resume Medis Helper RSBHHB

Berlaku mulai: 27 Oktober 2026 · Versi policy: 2.0

Ringkasan penting: extension ini dapat memproses data kesehatan dan data pribadi dari halaman eRM. Data hanya diproses ketika pengguna menjalankan fitur yang relevan. Data medis tidak dikirim ke layanan AI secara otomatis hanya karena extension terpasang.

1. Pengelola dan cakupan

Kebijakan ini berlaku untuk extension Chrome Resume Medis Helper RSBHHB dengan app ID resume-medis-reviewer. Extension membantu tenaga kesehatan mengambil, merangkum, mereview, dan memasukkan kembali data dari sistem eRM internal.

Pengembang dan pengelola teknis: Muhammad Syafrie Yunizar, MD.
Kontak privasi dan dukungan: syafrie.yunz@gmail.com

2. Data yang dapat diproses

Karena extension digunakan pada sistem rekam medis, data yang diproses dapat termasuk data pribadi dan data kesehatan yang sensitif. Jenis data bergantung pada halaman dan fitur yang dipilih pengguna, antara lain:

  • Identitas pasien, nomor rekam medis, tanggal lahir, jenis kelamin, dan informasi administratif yang tampil pada halaman eRM.
  • SOAP, CPPT, resume medis, anamnesis, pemeriksaan fisik, tanda vital, diagnosis, terapi, tindakan, operasi, konsultasi, dan rencana perawatan.
  • Kajian dokter IGD, laporan operasi, hasil laboratorium, radiologi, dan dokumen penunjang lainnya.
  • Isi PDF penunjang, teks hasil ekstraksi, metadata file, serta draft pekerjaan pengguna.
  • Input atau arahan yang ditulis pengguna untuk pemrosesan AI.
  • Pengaturan extension, provider/model AI, status penggunaan API key pribadi, dan sesi akses admin. API key pribadi disimpan secara lokal dan tidak ditampilkan pada halaman statistik.
  • Metadata operasional seperti app ID, username akses admin, fitur, provider, model, status berhasil/gagal, waktu, durasi, dan jumlah karakter input/output.

3. Sumber dan waktu pengumpulan

  • Data halaman eRM dibaca dari tab aktif setelah pengguna menekan tombol fitur seperti tarik SOAP, akses CPPT, tarik penunjang, atau memasukkan data ke resume.
  • Data AI dikirim hanya setelah pengguna menjalankan fitur AI, misalnya rangkuman, analisa klaim, improve inline, atau fitur AI lain yang tersedia.
  • Pengaturan dan draft dibuat ketika pengguna menyimpan pengaturan atau menggunakan alur draft extension.
  • Log penggunaan admin dibuat ketika backend memproses permintaan admin, termasuk panggilan AI.

4. Tujuan penggunaan

Data digunakan untuk tujuan yang berkaitan langsung dengan fungsi extension:

  • Menampilkan data dari halaman eRM aktif kepada pengguna.
  • Menyusun ringkasan SOAP, CPPT, penunjang, resume medis, dan analisa dokumentasi klaim.
  • Menghasilkan saran atau perbaikan teks berdasarkan instruksi pengguna.
  • Mengisi field resume medis atau RM 07 setelah pengguna menyetujui tindakan tersebut.
  • Mempertahankan draft lokal agar pekerjaan pengguna tidak hilang saat berpindah halaman.
  • Menyediakan autentikasi admin, konfigurasi provider AI, knowledge BPJS, audit penggunaan, dan troubleshooting operasional.

Extension bukan pengganti penilaian klinis. Hasil AI harus ditinjau dan diputuskan oleh tenaga kesehatan yang berwenang.

5. Penerima dan jalur pembagian data

Data tidak dijual dan tidak digunakan untuk iklan, pemasaran, penilaian kredit, atau data brokerage. Data hanya dibagikan kepada pihak yang diperlukan untuk menjalankan fungsi yang dipilih pengguna, dengan jalur berikut:

Penerima Data yang dapat diterima Tujuan dan pemicu
Browser dan perangkat pengguna Draft, teks medis, hasil ekstraksi PDF, pengaturan, dan status sesi. Penyimpanan lokal dan kelanjutan pekerjaan.
Supabase Edge Function milik pengelola Permintaan admin, app ID, username/sesi admin, konfigurasi, prompt AI, dan metadata penggunaan. Autentikasi admin, proxy provider admin, knowledge, log penggunaan, dan log prompt.
Provider AI yang dipilih Prompt, konteks medis yang diminta pengguna, serta data hasil ekstraksi yang diperlukan. Pada fitur vision, dapat termasuk metadata atau gambar jika fitur tersebut dipanggil. Rangkuman, analisa, perbaikan teks, atau keluaran AI setelah pengguna menjalankan fitur.

Provider AI dapat berupa Google Gemini, provider OpenAI-compatible, Sumopod, AImurah, X5Lab, atau endpoint custom sesuai konfigurasi pribadi/admin. Ketentuan penyimpanan dan pemrosesan provider tersebut juga dapat berlaku; pengguna dan institusi harus menilai kesesuaiannya dengan kebijakan internal dan hukum yang berlaku sebelum mengirim data medis.

6. Pemrosesan PDF dan data penunjang

PDF hasil penunjang diproses dengan parser lokal di browser terlebih dahulu bila memungkinkan. PDF mentah tidak dikirim ke provider AI hanya karena file dibuka. Teks atau hasil ekstraksi yang relevan dapat dikirim sebagai konteks AI ketika pengguna menekan fitur rangkuman atau fitur AI terkait.

Fitur OCR saat ini dinonaktifkan. Jika suatu saat diaktifkan kembali, perubahan alur pemrosesan akan didokumentasikan pada kebijakan ini sebelum digunakan.

7. Penyimpanan dan retensi

  • IndexedDB: draft lokal dapat berisi teks medis, sumber CPPT, hasil ekstraksi, metadata file, dan data penunjang yang diperlukan untuk melanjutkan pekerjaan. Draft memiliki masa retensi aplikasi tujuh hari sejak diperbarui dan dapat dihapus lebih awal oleh pengguna melalui alur extension atau pengaturan data situs Chrome.
  • chrome.storage.local: menyimpan pengaturan extension, API key pribadi, draft pengaturan, device ID, dan sesi akses admin pada perangkat pengguna.
  • Supabase: menyimpan konfigurasi provider admin per app ID, akun/sesi admin, knowledge, log penggunaan, dan log prompt AI. Log prompt dapat memuat system prompt, user prompt, provider, model, dan metadata gambar; karena itu log dapat mengandung data medis jika prompt berisi data tersebut.
  • Retensi backend: log backend dipertahankan untuk kebutuhan audit, keamanan, dan troubleshooting sampai dihapus oleh administrator sesuai kebijakan internal. Extension saat ini tidak menjanjikan penghapusan otomatis dengan jangka waktu tertentu untuk log backend.

8. Penghapusan dan permintaan privasi

Pengguna dapat menghapus draft dan pengaturan lokal melalui extension atau pengaturan data situs/extension Chrome. Untuk permintaan penghapusan, koreksi, atau pertanyaan tentang data yang tersimpan di backend, kirim email ke syafrie.yunz@gmail.com dengan menjelaskan app, username admin bila relevan, dan data yang diminta. Permintaan akan diverifikasi dan diproses sesuai kewenangan serta kebijakan internal rumah sakit.

9. Keamanan

  • Pengiriman ke backend dan provider dilakukan melalui koneksi HTTPS/TLS.
  • API key admin tidak dikirim ke UI sebagai nilai rahasia; extension hanya menerima status/configuration yang diperlukan.
  • Akses log prompt dibatasi melalui jalur admin dan app ID yang sesuai.
  • Pengguna tetap bertanggung jawab memastikan provider AI, akun, dan data yang diproses telah disetujui oleh institusi.

10. Kepatuhan penggunaan data

Pengelola menggunakan data hanya untuk menyediakan atau meningkatkan fungsi utama extension yang telah dijelaskan dalam kebijakan ini. Pengelola tidak menjual data, tidak menggunakannya untuk iklan personalisasi, dan tidak memberikan akses pembacaan manusia kecuali diperlukan untuk keamanan, dukungan yang diminta pengguna, audit yang berwenang, atau kewajiban hukum.

11. Izin Chrome

  • sidePanel: menampilkan antarmuka extension.
  • storage: menyimpan pengaturan dan draft lokal.
  • activeTab dan scripting: membaca atau mengisi halaman eRM setelah tindakan pengguna.
  • Host permissions: menjalankan fungsi pada alamat eRM internal yang didukung.

12. Perubahan kebijakan

Kebijakan ini dapat diperbarui apabila terdapat perubahan fitur, provider, cara penyimpanan, atau kewajiban hukum. Versi terbaru akan dipublikasikan pada URL ini. Perubahan material akan dijelaskan pada halaman extension atau melalui mekanisme pemberitahuan yang sesuai.
